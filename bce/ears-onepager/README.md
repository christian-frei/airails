# ears-onepager

> Added in this fork; not part of upstream [airails](https://github.com/AdamBien/airails).

Turns an [EARS](https://alistairmavin.com/ears/) spec into a one-pager: a process drawing derived
from the statements on the left, the statements themselves on the right, linked by requirement id
and colour. Emits an editable `.excalidraw`, a print-ready `.html`, and a `.pdf`.

## Scope

- **Derived, not drawn.** Every shape comes from a statement: an operation becomes an ellipse, each
  `If…then` a guard diamond plus a rejection box, the happy statement the outcome. Nothing is
  hand-placed, so the picture cannot disagree with the spec.
- **Generated by a script, not by the model.** `scripts/onepager` is a zero-dependency Java 25
  single-file program. A one-pager is ~100 Excalidraw elements and ~57 KB of JSON — deterministic
  work that costs no output tokens and cannot be malformed.
- **Deterministic.** Content-hash element ids, no timestamps: same input, byte-identical output, so
  regeneration diffs cleanly.
- **Two modes.** One capability (an `ears-spec` feature request or an `sbce` package doc), or
  `--system` across a source tree — BCs as nodes, the system doc's declared `## Components` wiring
  as edges, direction read from the relation wording rather than guessed.
- **Colours by role, not by hex.** Operation, guard, refused, outcome and six cycled group hues map
  to a palette defined in one place ([references/palette.md](references/palette.md)), so rebranding
  is a single edit. Drawn flat so the Excalidraw file and the PDF match; `--sketch` brings back the
  hand-drawn look.
- **Shows gaps rather than hiding them**: a group with no happy statement draws a grey box, a group
  with more than three guards says how many were not drawn.

## Provenance

## Usage

```
bce/ears-onepager/scripts/onepager payment-release.md --pdf
bce/ears-onepager/scripts/onepager src/main/java/acme/payment/package-info.java -o docs
bce/ears-onepager/scripts/onepager --system src/main/java -o docs --pdf
```

Needs a JDK 25+; `--pdf` needs Chrome, Chromium or Edge (set `CHROME` to point at one). Without a
browser, open the generated HTML and use Print → Save as PDF.

## Composition

- [`ears-spec`](../ears-spec) and [`sbce`](../sbce) own the specs this reads; it never edits them.
- [`ears-tests`](../ears-tests) decides whether a statement is *testable*; this one shows whether it
  is *showable*. Run `/ears-tests review` first — anything it flags also draws badly.
- [`mermaid`](../../documentation/mermaid), [`drawio`](../../documentation/drawio) and
  [`bce-diagrams`](../../documentation/bce-diagrams) are for hand-authored architecture diagrams.
  This one is generated, and is the only one bound to EARS statement ids.

The rules live in [SKILL.md](SKILL.md); the layout contract, colours and extension points in
[references/layout.md](references/layout.md).
